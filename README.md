# Tender Hack Казань 2026

Кейс «Автозаполнение ключевых характеристик в СТЕ». Пользователь описывает товар
своими словами, а сервис находит конечный код КТРУ, заполняет характеристики в
унифицированном виде, показывает, как сужается выбор кодов, и объясняет каждую
найденную ошибку.

## Быстрый старт

```bash
uv sync
uv run ruff check . && uv run ruff format --check .
```

## Подготовка КТРУ

Исходные ZIP кладутся в `КТРУ_raw/`. Сборщик берёт только
`nsiKTRUNew_all_actual_*.xml`, игнорирует `not-actual` и оставляет последнюю версию
каждого кода. В рабочий справочник попадают только действующие товары из трёх категорий:

- одежда — ОКПД2 `14.*`;
- мебель — ОКПД2 `31.*`;
- инструменты — ОКПД2 `25.73.*` и `28.24.*`.

Услуги и позиции, которые ещё не действуют на заданную дату, исключаются. Дата
выгрузки проверяется по имени ZIP:

```bash
uv run python scripts/build_ktru_actual.py \
  --expected-date 2026-10-05 \
  --as-of 2026-10-05
```

Результат записывается в `data/processed/ktru.json`. Это обычный JSON с двумя полями:

- `metadata` — дата выгрузки, дата действия, число XML и позиций по категориям;
- `positions` — рабочий массив позиций КТРУ.

В каждой позиции остаются только нужные приложению поля: код, название, категория,
ОКПД2, тип позиции, код родителя, единицы и характеристики. Описание добавляется, только
если оно есть в КТРУ. Пример сокращённой позиции:

```json
{
  "code": "25.73.30.141-00000001",
  "name": "Молоток",
  "category": "tools",
  "okpd2_code": "25.73.30.141",
  "position_type": "final",
  "parent_code": "25.73.30.141-00000011",
  "units": [{"code": "796", "name": "Штука"}],
  "characteristics": [
    {
      "code": "eef63e69-7",
      "name": "Безынерционный",
      "type": "text",
      "selection": "single",
      "required": false,
      "values": ["Да", "Нет"]
    },
    {
      "code": "f78c450e-2",
      "name": "Масса молотка",
      "type": "number",
      "selection": "single",
      "required": false,
      "unit": {"code": "166", "name": "Килограмм"},
      "values": [
        {"max": 0.1, "max_inclusive": false},
        {"min": 0.1, "min_inclusive": true, "max": 0.2, "max_inclusive": false}
      ]
    }
  ]
}
```

`values` содержит строки для качественных характеристик, числа для точных числовых
значений и объекты `min`/`max` для диапазонов. Внутренние коды вариантов и пустые поля
из XML в рабочий файл не переносятся.

Файлы `data/` и `КТРУ_raw/` не попадают в Git.

## Загрузка справочника

`load_data` возвращает готовый список позиций. Его можно ограничить категорией и только
конечными кодами. `expected_date` защищает от случайной загрузки другой версии данных.

```python
from datetime import date

from scripts.dataloader import load_data

data = load_data(
    expected_date=date(2026, 10, 5),
    category="tools",
    final_only=True,
)
```

Практический порядок подбора:

1. Найти шаблон по `name` внутри нужной `category`.
2. Получить его конечные варианты по `parent_code == template["code"]`.
3. Сужать варианты по характеристикам с `selection == "fixed"`.
4. По полю `required` определить, какие характеристики ещё нужно спросить.
5. Проверять введённое число по `values` и приводить его к единице из `unit`.

Для просмотра одной конечной позиции из командной строки:

```bash
uv run python scripts/dataloader.py \
  --expected-date 2026-10-05 \
  --category tools \
  --final-only \
  --limit 1
```
