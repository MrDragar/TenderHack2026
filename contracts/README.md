# Контракты между модулями

Здесь только типы данных и сигнатуры шагов, реализации нет. Модули пайплайна импортируют
отсюда и не импортируют друг друга, соединяет их одна функция run.

## Правила
- Контракт меняем только объявив всем. Молча менять нельзя: на нём пишут параллельно.
- Поля результата определяют те, кто им пользуется (замер, веб), а не тот, кто его делает.
- Данные проверяем только на входе в систему: при сборке справочника и на входе веба.
  Внутри пайплайна формат не перепроверяем, за него отвечают типы.
- Типы проверяет `uv run ty check`, запускаем перед слиянием вместе с ruff и тестами.
- Всё передаётся обычными словарями и списками, TypedDict только описывает их форму.

## Что где
| Файл | Что | Кто делает | Кто пользуется |
|---|---|---|---|
| ref.py | Position, Characteristic: справочник КТРУ | сборка справочника | все шаги, эталон |
| ref.py | Portal: характеристики портала | разбор xlsx | шаг характеристик |
| pipeline.py | Candidates | шаг кандидатов | шаги характеристик и сужения |
| pipeline.py | FoundChar | шаг характеристик | шаг сужения |
| pipeline.py | Result | шаг сужения | run, замер, веб |
| pipeline.py | FindCandidates, ExtractChars, Narrow, Run | | сигнатуры шагов |
| eval.py | GoldExample | эталонный набор | замер |

## Справочник КТРУ (ref.py)
Собирается scripts/build_ktru_actual.py, загружается load_data из scripts/dataloader.py.
- position_type: "template" это шаблон, "final" конечный код. У конечного parent_code
  указывает на шаблон, но у 51 конечного кода родителя нет.
- selection: "fixed" значение неизменяемое, по таким характеристикам различаются дети
  одного шаблона. "single" и "multiple" это выбор заказчика из списка.
- values: строка это текстовое значение, число это точное значение, Range это диапазон.
  У Range может не быть min или max, *_inclusive говорит, строгая ли граница. В одной
  характеристике бывают вперемешку числа и диапазоны («0 шт», «от 1 шт»).
- unit: одна на характеристику и только у числовых, у 176 числовых её нет.
- description есть только у 12 позиций.

## Характеристики портала (ref.py, черновик)
Portal: ключ это название из колонки «Конечная категория ПП», значение это список её
характеристик со второго листа xlsx. type это тип значения с портала как есть
(«Справочник», «Текст», «Целое числовое значение» и т. п.).

## Шаги пайплайна (pipeline.py, черновик)
```
FindCandidates(text, ref) → Candidates
ExtractChars(text, candidates, ref, portal) → list[FoundChar]
Narrow(candidates, chars, ref) → Result
Run(text) → Result
```
- Candidates: категория (None, если не определили) и только конечные коды с оценкой
  score от 0 до 1.
- FoundChar: source "ktru", "portal" или "new". fragment это кусок исходного текста, из
  которого взято значение.
- Result:
  - steps: шаги сужения, left это сколько кодов осталось после шага;
  - code None, если однозначного кода нет, тогда question: какую характеристику спросить
    и варианты ответа;
  - missing_required: названия обязательных характеристик, которые не заполнены;
  - remarks: правки «было, стало, почему».

Шаг объявляет, что выполняет контракт, при подключении в run:
```python
from contracts.pipeline import FindCandidates

find_candidates: FindCandidates = candidates.find
```
Если сигнатура или форма результата не совпадает, ty check упадёт.

## Эталонный набор (eval.py, черновик)
GoldExample: текст и ожидаемые категория, код и характеристики. code None для примеров,
где правильный ответ это вопрос. Примеры из выгрузки портала это данные организаторов,
такой файл лежит в data/ и в git не попадает.
