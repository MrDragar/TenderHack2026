# Проверка новых характеристик на мусор

Жюри: «новые характеристики — кандидаты, их одобряет модератор, мусор создавать нельзя».
Проверку проходят пары «Название: значение», которых нет ни в КТРУ, ни на портале,
и неразобранные слова описания. Код: pipeline/trash.py, встраивание: checked в
pipeline/run.py.


## Как решаем
1. **Память модератора** (data/moderation.json). Такое название уже одобряли — это
   характеристика с единым названием из памяти: «ручки противоскользящие» ложатся
   в «Наличие противоскользящей ручки». Отклоняли — мусор. Модель не спрашиваем.
2. **Контакты и ссылки** — мусор без модели: телефон, почта, сайт свойством товара
   не бывают.
3. **Zero-shot NLI.** Посылка «Молоток. Ручка противоскользящая: да», две гипотезы:
   «Это свойство или характеристика товара» и «Это реклама, контакты, цена или условия
   продажи». Вероятность свойства p = P(свойство) / (P(свойство) + P(мусор)).
   - p < TRASH_BELOW — мусор, характеристику не создаём, просим поправить описание;
   - p > PROPERTY_ABOVE — свойство, новая характеристика ждёт модератора;
   - между ними — спорное. Если модератор решал похожее, берём его вердикт,
     но не название. Иначе решает модератор.
4. **Нет модели или torch** — всё, кроме памяти и контактов, спорное и уходит модератору.
   Пайплайн не падает.

Почему схема не устаревает: модель отвечает не на вопрос «видели ли мы это», а на вопрос
«правдоподобно ли это свойство товара». Новизну определяет память. Каждое решение
модератора действует со следующего запроса без переобучения. Ошибки модели на краях
ограничены порогами, а спорное видит человек.

Пайплайн и сервер всегда держат модель на CPU: видеокарта нужна только обучению.

Модель: cointegrated/rubert-base-cased-nli-threeway. Русская, открытая, ~180 млн
параметров, ~700 МБ. Один запрос — одна пачка пар, на CPU десятки миллисекунд.

Решение модератора: `POST /api/moderate` с телом
`{"told": "Ручка противоскользящая", "name": "Наличие противоскользящей ручки",
"product": "Молоток", "approved": true}`. В выдаче у новой характеристики поле `check`:
`verdict` (property, unsure, trash), `why`, `score`, `name`. Мусорные куски лежат
в `unknown` с тем же `check`.


## Что запустить на хосте
Здесь ничего тяжёлого не запускали. На хосте с данными в data/processed:

```bash
# 1. Зависимости модели (torch и transformers), без них пайплайн работает без NLI.
uv sync --group nli

# 2. Тесты, модель не нужна.
uv run pytest
uv run ruff check && uv run ruff format --check

# 3. Скачать модель в models/nli (нужен интернет, GPU не нужен).
uv run python -m scripts.download_nli

# 4. Посмотреть примеры, на которых учим и меряем.
uv run python -m scripts.trash_examples 30

# 5. Замер zero-shot и подбор порогов на dev. По умолчанию на CPU, как в пайплайне,
#    и время в выводе тоже для CPU. Быстрее на свободной видеокарте: --device cuda.
uv run python -m scripts.eval_trash --limit 2000

# 6. Глазами: пара в КТРУ, новая хорошая, объявление, контакт.
uv run python -m pipeline.run "Молоток слесарный 500 г, ручка противоскользящая: да, \
продам срочно, телефон: +7 999 111 22 33"
```

Пороги из шага 5 переносим руками в TRASH_BELOW и PROPERTY_ABOVE (pipeline/trash.py).
Цель порогов: выброшенное молча — мусор не меньше чем в 97% случаев, принятое
уверенно — свойство не меньше чем в 90%.


## Дообучение (необязательно, GPU 6 ГБ)
Учим ту же NLI-задачу на примерах без ручной разметки (scripts/trash_examples.py):
- свойство: характеристика КТРУ или портала со своим товаром, одобренное модератором;
- мусор: характеристика чужой категории («Стол письменный. Размер воротника: 42»),
  контакты, цены, торг, бессмыслица, отклонённое модератором.

```bash
uv run python -m scripts.train_trash --epochs 2 --batch 32   # ~3 ГБ VRAM, fp16
uv run python -m scripts.eval_trash --model models/nli       # было
uv run python -m scripts.eval_trash --model models/nli-trash # стало
```

Если не хватает памяти, уменьшить `--batch` до 16. Пайплайн сам берёт models/nli-trash,
если папка есть. Оставляем дообученную, только если AUC и доля «выброшено» у свойств
лучше, чем у исходной. Иначе удалить models/nli-trash. Учимся на dev, test
(`--test`) запускает только человек.
